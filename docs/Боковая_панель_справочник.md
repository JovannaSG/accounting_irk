# Боковая панель «ИИ-Аудитор 1С»: все опции

Справочник по всем элементам боковой панели приложения. Настройки,
сделанные здесь, применяются при **следующем** запуске аудита — перезапуск
приложения не требуется.

---

## 1. Вход и выход

- **«🔓 Выйти»** (верх боковой панели) — появляется только когда пользователь
  вошёл в систему. Очищает сессию (пользователь, роль, доступы, загруженную
  историю) и возвращает на экран входа.
- **«🔐 Вход в приложение»** — экран логина (показывается в основной области,
  когда аутентификация включена). Учётные записи задаёт администратор.

> Если аутентификация выключена, приложение работает «открыто»: видны все
> базы, дашборд и история.

---

## 2. «📥 Загрузка данных»

Заголовок раздела. Далее — **«Источник данных»** — главный переключатель
(radio) из трёх режимов:

1. **«📁 Файл (CSV/XLS/XLSX/HTML)»** — ручная загрузка отчёта ОСВ с диска.
2. **«☁️ 1С:Фреш (OData)»** — подключение к одной базе 1С:Фреш напрямую.
3. **«📊 Аудит всех баз»** — массовый аудит баз из `client_databases.json`.

---

### 2.1. 📁 Файл (CSV/XLS/XLSX/HTML)

- **«ОСВ (CSV / XLS / XLSX / HTML)»** — загрузка одного или нескольких файлов
  оборотно-сальдовой ведомости (отчёт 1С, сохранённый как Excel или HTML).
  MXL не поддерживается. Допустимые расширения: `csv`, `xls`, `xlsx`, `html`,
  `htm`.
- **«Режим нескольких файлов»**:
  - *Объединить в одну базу (один аудит)* — если файлы это разные месяцы одной
    компании;
  - *Проверить каждый отдельно* — если файлы относятся к разным базам или
    организациям.
- **«Реестр документов (CSV, опционально)»** — движения по контрагентам
  (отгрузки/оплаты/авансы) для проверки **4.5 «Незакрытые расчёты с
  контрагентами»** и расхождения документов с остатками ОСВ. Если в реестре
  есть колонка **«Назначение»**, включается NLP-проверка формулировок платежей
  (115-ФЗ). Без реестра проверки 4.5 не работают.

### 2.2. ☁️ 1С:Фреш (OData)

В этом режиме всегда выполняется один аудит (режим нескольких файлов не
применяется).

- **«🔑 Доступ к 1С:Фреш»** (раскрывающийся блок):
  - **URL базы** — адрес базы. Подставляется автоматически: бухгалтеру — его
    единственная назначенная база; админу/без входа — значение переменной
    окружения `ONEC_URL` (если задана); иначе поле пустое. Для бухгалтера
    подсказка «Выберите назначенную базу...».
  - **Пользователь** — по умолчанию `odata.user` (или `ONEC_USER`).
  - **Пароль** — пароль пользователя 1С.
- **«Период с» / «Период по»** — даты периода для выгрузки ОСВ (по умолчанию —
  с начала года по сегодня).
- **«📡 Загрузить ОСВ из 1С»** — загрузить данные и перейти к аудиту.

> Если пользователь вошёл как **бухгалтер**, подключение к базе вне его
> списка доступа блокируется («Доступ к этой базе не назначен»).

### 2.3. 📊 Аудит всех баз

Массовая проверка всех баз из файла **`client_databases.json`** (в корне
проекта). Каждая база — это словарь `{name, url, login, password}`; имя может
иметь вид `"1;Название"` — тогда номер попадёт в первую колонку сводного
дашборда («Бухгалтер»), а в списке баз и в колонке «База» будет показано
только название.

- **«Доступно баз: N»** — сколько баз доступно текущему пользователю.
- **«Список баз»** (раскрывающийся) — нумерованный список доступных баз
  (например `1. Агенство_Инвест_Авиа`). Номер префикса `N;` убирается.
- Если баз не назначено — сообщение **«Вам не назначено ни одной базы для
  массового аудита. Обратитесь к администратору.»**
- **«Период с» / «Период по»** — общий период для всех баз.
- **«📡 Загрузить все базы»** — запустить выгрузку и аудит всех доступных баз.

> Доступность баз зависит от роли: **админ / без входа** — все базы;
> **бухгалтер** — только базы, URL которых есть в его списке доступа
> (`allowed_urls`). Доступы задаются в `users.json` / в таблице `users` БД.

> **Важно:** в массовом режиме реестр документов не загружается — проверка
> **4.5** и **NLP (115-ФЗ)** здесь недоступны (работают только при ручной
> загрузке файла или в одиночном подключении 1С:Фреш). Названия баз могут
> задаваться как `"N;Название"` — номер виден только в дашборде.

## 3. «⚙️ Настройки проверок»

Блок настраивает правила проверок ТЗ. По умолчанию включены проверки 4.1–4.5.

**Проверки ТЗ** (включены по умолчанию):

- **4.1 «Красное сальдо»** — активные счета с кредитовым остатком и пассивные
  с дебетовым.
- **4.2 «Развернутое сальдо»** — скачки и незакрытые остатки по аналитике
  (субконто/контрагентам) вместо свёрнутого сальдо.
- **4.3 «Незакрытое сальдо на конец месяца»** — остатки по закрываемым счетам.
- **4.4 «Счет 000»** — служебный счет 000 с нарушениями.
- **4.5 «Незакрытые расчеты с контрагентами»** — работают только при
  загруженном «Реестре документов (CSV)».

**Дополнительно:**

- **«Контроль групп счетов (4.3)»** (по умолчанию выключен) — незакрытые
  остатки на конец периода по группам: авансы, РБП, товары, денежные средства,
  кредиты.
- **«Зависшее сальдо между периодами»** (по умолчанию выключен) — предупреждает,
  если остаток по счету не меняется несколько периодов подряд. Требует данных
  за **2+ периода** в одном запуске (режим «🗓 За период в целом»). В режиме
  «📅 По месяцам» не срабатывает.

**Текстовые настройки:**

- **«Организация»** — название организации, подставляется в отчет (Excel/PDF).
- **«Бухгалтер»** — ФИО бухгалтера базы; отображается в сводном дашборде (если
  у базы нет числового префикса `N;` — номер занимает первое место).
- **«Закрываемые счета (через запятую)»** — счета, которые должны быть закрыты
  в конце месяца (проверка 4.3). По умолчанию: `25, 26, 44, 90, 91, 99`.
- **«План счетов: Тип (код:тип)»** — дополнительные типы счетов для определения
  красного сальдо, формат `Код:Тип` через запятую. Например `51:A, 60.01:AP`.

## 4. «ML-проверки»

Блок опциональных эвристических проверок (по умолчанию включены).

- **«Включить ML-проверки»** — общий выключатель блока.
- **«Нетипичные суммы операций»** — операции, чья сумма статистически выделяется
  по истории контрагента (медиана + MAD).
- **«Скачки оборотов между периодами»** — резкий рост/падение оборотов по счету
  между периодами (нужны данные за 2+ периода).
- **«Дубли контрагентов»** — нечеткий поиск похожих названий
  («ООО Ромашка» vs «Ромашка, ООО»).
- **«NLP: назначения платежей (115-ФЗ)»** — поиск рискованных формулировок в
  колонке «Назначение» реестра документов (обнал, займы без договора,
  расплывчатые основания).
- **«Порог сходства дублей, %»** — чувствительность поиска дублей
  (по умолчанию 90%, диапазон 70–100%).
- **«Порог аномалии суммы, ₽»** — минимальная сумма для признания операции
  аномальной (по умолчанию 1 000 ₽).

## 5. Периоды и режим аудита (появляются после загрузки данных)

Эти секции появляются в боковой панели под блоками настроек после того, как
загружены данные (файл, OData или массовая выгрузка).

- **«Период проверки»** (мультивыбор) — периоды из загруженных данных, по
  которым пройдёт аудит. По умолчанию выбраны все. Если выбор пуст или не
  попадает в данные — сообщение «Выбранные фильтры не содержат данных».
- **«Группировка периодов»**:
  - *«🗓 За период в целом»* — все выбранные периоды анализируются одним
    блоком (проверки «Зависшее сальдо» и «Скачки оборотов» работают только
    здесь — нужны 2+ периода);
  - *«📅 По месяцам»* — каждый период проверяется отдельно; в сводном
    дашборде каждая строка — отдельный период базы (к имени базы добавляется
    период).
- **«Режим аудита»**:
  - *«Полный»* — все данные;
  - *«По счетам»* — появляется «Выберите счета» (мультивыбор); аудит только
    выбранных счетов;
  - *«По контрагенту»* — появляется «Выберите контрагентов»; аудит только
    выбранных контрагентов/субконто.
  Если ни один счет/контрагент не выбран — предупреждение «Выберите хотя бы
  один счет/контрагента».
- Капшн **«📄 Источник: … | Орг.: …»** — отображает текущий источник данных и
  организацию (если известна).

Разделы разделены в панели горизонтальными линиями; ниже — кнопка
**«🚀 Запустить Аудит»** (в основной области): запускает проверку с текущими
настройками.

---

## 6. Типовые подсказки после запуска

- `⚠️ Внимание: подозрительные данные в базе «...»` — в данных ОСВ найдены
  аномалии структуры (задвоения, пустые строки и т.п.) — аудит продолжается.
- `⚠️ Пропущена база '...'` — база не загрузилась (ошибка подключения/данных) —
  выполняется переход к следующей базе.
- Результаты выводятся во вкладках «Результаты проверок» (сводный дашборд с
  drill-down по базам) и «Динамика (Сравнение)».
