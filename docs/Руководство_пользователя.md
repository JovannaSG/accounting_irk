# Руководство пользователя «ИИ-Аудитор 1С»

Описывает работу с приложением: вход, загрузка данных, запуск аудита,
разбор результатов и типовые проблемы. Настройки боковой панели подробно
описаны в отдельном документе **«Боковая_панель_справочник.md»**.

---

## 1. Начало работы

- Если вход включён, приложение показывает экран **«🔐 Вход в приложение»**.
  Логин выдаётся администратором; пароль хранится только в виде хэша.
- После входа вверху боковой панели появляется кнопка **«🔓 Выйти»**.
- Если вход выключен — приложение работает «открыто» (видны все базы).

## 2. Типовой сценарий

1. В боковой панели выберите **источник данных**:
   - **«📁 Файл (CSV/XLS/XLSX/HTML)»** — отчёт ОСВ с диска (+ опционально
     реестр документов);
   - **«☁️ 1С:Фреш (OData)»** — прямая выгрузка ОСВ из одной базы;
   - **«📊 Аудит всех баз»** — массовая проверка назначенных баз.
2. Загрузите данные (кнопки «📡 Загрузить ОСВ из 1С» / «📡 Загрузить все
   базы», либо выбор файлов).
3. При необходимости настройте проверки («⚙️ Настройки проверок»,
   «ML-проверки», периоды и режим аудита).
4. Нажмите **«🚀 Запустить Аудит»** — результат появится во вкладках
   «Результаты проверок» и «Динамика (Сравнение)».

## 3. Форматы данных

### ОСВ (оборотно-сальдовая ведомость)

Отчёт 1С, сохранённый как **Excel, CSV или HTML**. MXL **не** поддерживается.

Обязательные колонки:

- **Счет** — код счёта (например `60.01`);
- **Тип** — вид счёта: `A` (активный), `P` (пассивный), `AP`
  (активно-пассивный);
- **КонецДебет** и **КонецКредит** — конечное сальдо.

Остальные колонки (если есть): `Период`, `Субконто`, `Организация`,
`Договор`, `НачалоДебет`, `НачалоКредит`, `ОборотДебет`, `ОборотКредит`.

Допустимые русские/латинские варианты имён колонок распознаются
автоматически (например `Счёт`/`Счет`/`account`, `Субконто`/`Аналитика`,
`Назначение`/`purpose`). Числовые значения не должны содержать мусора —
иначе аудит остановится с описанием причины.

### Реестр документов (CSV)

Опциональный файл для проверки расчётов с контрагентами (4.5).

Обязательные колонки: **Дата**, **Контрагент**, **Вид**, **Сумма**.
Опциональные: **Документ**, **Счет**, **Назначение**.

Если есть колонка **«Назначение»**, включается **NLP-проверка** рискованных
формулировок платежей (115-ФЗ).

## 4. Результаты проверки

### 4.1. Заголовок базы и метрики

По выбранной базе показываются: **Бухгалтер**, **Дата просмотра**,
**Красных флагов** (число находок), **Пользователь** (кто запускал).

### 4.2. Сводный дашборд по базам

- Одна строка на базу (или на базу+период, если используется «По месяцам»).
- **Первая колонка** — номер базы, если имя задано как `"N;Название"`;
  иначе — ФИО бухгалтера. Пустые ячейки обозначаются **«—»**.
- Клик по строке открывает панель «Детализация по счетам» ниже.

### 4.3. Детализация по счетам

Находки сгруппированы в блоки:

- **🔴 Блок 1. Красное сальдо (отрицательные остатки)** — проверка 4.1:
  отрицательный остаток по активному счёту (или дебетовый по пассивному).
- **🟡 Блок 2. Незакрытые счета (на конец месяца)** — проверки 4.3–4.4:
  не закрытые на конец месяца счета, счёт 000, зависшее сальдо (опционально).
- **🟠 Блок 3. Развёрнутое сальдо и расчёты с контрагентами** — проверки 4.2
  и 4.5: дебиторка и кредиторка по одной аналитике, незакрытые расчёты,
  «аванс и долг одновременно», расхождение документов и остатков ОСВ.
- **🔵 Блок 4. Расчётный счёт (нет движений по 51)** — отсутствие операций по
  расчётному счёту за период.
- **🔎 ML-дубли контрагентов** — похожие названия, которые могут «раздвоить»
  взаиморасчёты.

Кроме блоков, по каждому счёту открывается свёртка **«📄 Счёт N — нарушений: k»**: таблица находок (Проверка, Период, Уровень, Сумма, Субконто, Комментарий,
Договор), ОСВ по счёту, список периодов и аналитика по субконто. К каждой
находке прилагается **рекомендация по исправлению**.

### 4.4. Экспорт отчёта

Для выбранной базы доступны кнопки **«💾 Выгрузить отчет в Excel»** и
**«💾 Выгрузить отчет в PDF»**. В архивных записях экспорт восстанавливает
находки из сохранённой истории; если запись создана более старой логикой
проверок, приложение предупредит об этом.

### 4.5. Управление историей

В дашборде есть раздел **«🗑️ Управление историей (удаление из БД)»**:
можно удалить все проверки, выполненные **до выбранной даты** (включительно).
Удаление **безвозвратно** и ограничено правами: бухгалтер удаляет только
свои прогоны и записи своих баз, админ — всё. Будьте внимательны — отменить
нельзя.

### 4.6. Сравнение двух проверок (вкладка «Динамика»)

- Выберите «Было» и «Стало» из списка проверок.
- Нажмите «Сравнить базы» — приложение покажет **«Исправлено ошибок: N»** и
  таблицу разрешённых проблем.

## 5. Статусы и уровни

- **Статус аудита**: `ok` (Успешно) / `warning` (Есть ошибки) / `error`.
- **Уровень находки**: `error` (грубая ошибка) / `warning` (требует
  внимания).

## 6. Устранение неполадок

| Сообщение | Причина / что делать |
|---|---|
| «Отсутствуют обязательные колонки: …» | Файл не похож на ОСВ: проверьте колонки (Счет, Тип, КонецДебет, КонецКредит). |
| «Колонка … содержит нечисловые значения» | В числовой колонке мусор — почистите выгрузку из 1С. |
| «Недопустимые значения Тип: …» | Тип счёта должен быть A / P / AP. |
| «Файл ОСВ пуст» | В файле нет данных. |
| «Выбранные фильтры не содержат данных» | Периоды/режим аудита не пересекаются с данными. |
| «Вам не назначено ни одной базы для массового аудита» | У бухгалтера нет баз (или URL в доступах не совпадает с файлом баз) — к администратору. |
| «Доступ к этой базе не назначен» | Попытка подключиться к базе вне списка доступа — к администратору. |
| «Пропущена база '…'» | База не загрузилась (ошибка 1С/подключения/данных) — проверьте URL/логин/пароль. |
| `⚠️ Внимание: подозрительные данные в базе «…»` | Найдены аномалии структуры — аудит продолжается, но стоит уточнить данные. |
| MXL не читается | Откройте отчёт в 1С и сохраните как Excel или HTML. |

Подробности работы с боковой панелью — в **«Боковая_панель_справочник.md»**,
настройка доступа и баз — в **«Руководство_администратора.md»**.
