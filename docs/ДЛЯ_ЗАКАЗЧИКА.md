# ИИ-Аудитор 1С: как работает программа

## 1. Идея (для заказчика)

Бухгалтер вручную «прочесывает» оборотно-сальдовую ведомость, чтобы найти ошибки: минусовые остатки, незакрытые счета, «висящие» суммы. Программа делает то же самое автоматически: вы загружаете ОСВ из 1С, она находит проблемные строки, показывает их списком и выгружает отчет в Excel.

Ключевое: **программа работает без интеграции с 1С** — данные загружаются обычным файлом (выгрузкой из 1С). Это безопасно и не требует доступа к базе.

## 2. Как это устроено (поток данных)

```
Файл ОСВ (XLS/XLSX/HTML/CSV)  ──►  loaders.py ──►  «каноническая» таблица
                                                    (единый формат для всех проверок)
                                                          │
                                                     auditor.py
                                                          │
                              5 проверок по ТЗ §4 ─────────┤
                                                          │
                                                    отчет: сводный +
                                                    детальный + Excel
```

## 3. Структура кода

| Файл | Роль |
|---|---|
| `app.py` | Веб-интерфейс (Streamlit): загрузка файлов, настройки, показ результатов |
| `loaders.py` | «Приёмник данных»: распознает формат файла и превращает любую выгрузку 1С в единый формат таблицы |
| `auditor.py` | Ядро: сами проверки (правила из ТЗ) + формирование отчетов |
| `api_client.py` | Опциональный доступ к данным 1С напрямую через OData (в т.ч. облачный 1С:Фреш) |
| `tests/` | Автотесты, включая реальные выгрузки 1С и OData-клиента |

## 4. Как загрузчик превращает «сырую» выгрузку в таблицу

Выгрузка из 1С — это человеко-ориентированный отчет: многострочный заголовок («Сальдо на начало периода / Обороты за период / Сальдо на конец периода», у каждого — подколонки «Дебет/Кредит»), строки-аналитика, итоговые строки, суммы с пробелами/запятыми. Парсер (`loaders.py`) делает:

1. **Определяет формат** по расширению и содержимому файла (CSV / XLS / XLSX / HTML). Важно: 1С часто сохраняет HTML-выгрузку с расширением `.xls` — программа распознаёт это по содержимому.
2. **Находит начало таблицы** — первую строку с номером счета (например, `000`, `51`, `60.01`).
3. **Собирает строки**: у строк-счетов берет код счета; строки-аналитики (банковские счета, договоры, «Курсовые разницы») **наследуют родительский счет** — так аналитика не теряется.
4. **Отбрасывает мусор**: итоговые строки («Итого», «Total»), пустые строки, заголовки.
5. **Правильно читает числа** в обеих локалях: `112,748,946.35` и `1 234 567,89` → число. Красные (отрицательные) остатки 1С пишет в «правильную» колонку с минусом — это тоже учитывается.
6. **Определяет Тип счета** (A/P/AP): по встроенному «плану счетов» (как в 1С: 51 — активный, 66 — пассивный, 60 — активно-пассивный), с возможностью добавить свои коды в настройках. Для неизвестных счетов — эвристика по остаткам.

## 5. Пять проверок (логика, по ТЗ §4)

**4.1 Красное сальдо** (уровень: ошибка)
Сальдо «в минус»: у активного счета кредитовый остаток (например, касса 50 с минусом), у пассивного — дебетовый (например, 66 «Кредиты банка» с дебетом). 1С хранит такие остатки как отрицательные числа в своей колонке — программа учитывает оба способа записи. Тип счета берется из плана счетов (как в 1С:Бухгалтерия 8.3: 60/62/71/73/84 — активно-пассивные), поэтому не путаются «красное сальдо» и «просто активно-пассивный счет». Например, непокрытый убыток на 84 или перерасход подотчетного лица на 71 — это не красное сальдо.
На вашем файле: найдено красное сальдо по счету 20.

**4.2 Развернутое сальдо** (уровень: предупреждение)
Когда по одному **контрагенту/аналитике** одновременно висит и дебиторка, и кредиторка (например, аванс выдали и долг есть у одного поставщика). Важно: по счету целиком (без аналитики) наличие и Д, и К — это нормально для активно-пассивных счетов, поэтому проверка срабатывает только по аналитике — иначе был бы шум.

**4.3 Незакрытое сальдо на конец месяца** (ошибка) + **зависшее сальдо** (предупреждение)
- Первая часть: остаток по «закрываемым» счетам (по умолчанию 25, 26, 44, 90, 91, 99) после закрытия месяца. Например, на вашем файле не закрыты 26, 90, 91, 99.
- Вторая часть: сальдо, которое **не меняется между периодами** (например, сумма «висит» и в январе, и в феврале) — признак забытой операции. Требует данных за 2+ периода.

**4.4 Счет 000** (ошибка)
Служебный счет для вспомогательных операций — он должен быть нулевым на конец периода. Любой остаток — ошибка. На вашем файле: остаток ~112 млн по счету 000 — заметная проблема.

**4.5 Незакрытые расчеты с контрагентами** (ошибка/предупреждение)
Если загружен реестр документов (отгрузки/оплаты/авансы) — программа «сводит» их по каждому контрагенту: отгрузка без оплаты, аванс без отгрузки, расхождение между документами и остатками ОСВ.
Если реестр не загружен — работает эвристика: на счетах расчетов (60/62/76) ищет контрагента с одновременным долгом и авансом.
Для каждого незакрытого остатка программа дополнительно указывает **ожидаемый документ** — что должно прийти/пройти, чтобы закрыть расчет («ожидается оплата по отгрузке от 12.11.2025 на 100 000,00» или «ожидается отгрузка/зачет по авансу…»), и **старейший непогашенный документ** (возраст в днях).

Проверки 4.1–4.5 можно отключать по одной в боковой панели (например, проверять только 4.4 и 4.5).

**ML-проверки (аномалии и дубли)** — программа смотрит на данные статистически, как опытный аудитор:
- **Нетипичная сумма операции** — если контрагент всегда платил ~50 000 ₽, а один раз пришел чек на 5 000 000 ₽, программа это выделит (проверяет историю по каждому контрагенту);
- **Скачок оборотов между периодами** — резкий рост/падение оборотов по счету, который стоит проверить;
- **Дубли контрагентов** — похожие названия («ООО Ромашка» и «Ромашка, ООО»), которые могут «раздвоить» взаиморасчеты.

ML-проверки можно включить/выключить в боковой панели; их результаты попадают в тот же отчет (желтая пометка «предупреждение»).

## 6. Отчеты (ТЗ §6)

- **Сводный**: статус проверки, число «флагов», общая сумма отклонений, разбивка по видам проверок + **рекомендация** к каждой находке (что проверить или исправить).
- **Детальный**: каждая найденная строка — тип ошибки, счет, субконто, контрагент, сумма, период, комментарий.
- **Выгрузка в Excel** с цветовой индикацией (красный/желтый), лист «Об отчете» с организацией и периодом — по кнопке в интерфейсе.
- **Выгрузка в PDF** — печатная форма отчета (шапка с реквизитами, сводный/детальный отчет, рекомендации).
- В интерфейсе результаты можно **фильтровать** по проверке, счету и контрагенту (фильтр не влияет на выгрузку — в файл попадает полный отчет).

Дополнительные возможности:
- **Период возникновения**: для красного сальдо и незакрытых счетов в комментарии указывается, **с какого периода** появился остаток («отрицательное сальдо с 31.01.2026»).
- **Контроль групп счетов** (включается чекбоксом): проверка незакрытых остатков по группам — авансы, расходы будущих периодов, товары, денежные средства, кредиты и займы.

## 7. Что важно знать заказчику (границы прототипа)

- **Формат MXL не поддерживается** (это закрытый бинарный формат 1С). Нужно сохранить отчет как **Excel или HTML** — делается в 1С за один клик (Файл → Сохранить как).
- Обычная ОСВ-выгрузка **не содержит аналитики** (данные по контрагентам/договорам). Поэтому проверки «развернутое сальдо» и «контрагенты» полноценно работают либо при выгрузке с аналитикой, либо при загрузке реестра документов.
- Это **прототип, в первую очередь — без интеграции с 1С** (безопасная работа с файлами-выгрузками). Опционально предусмотрено подключение к базе через **OData API** — в том числе к облачному сервису **1С:Фреш** (см. раздел 8), чтобы не выгружать файлы вручную.

## 8. Подключение к облаку 1С:Фреш через OData (опция)

Если заказчик работает в облачном сервисе **1С:Фреш** (1cfresh.com), программу можно подключить к базе напрямую — без ручной выгрузки ОСВ. Фреш поддерживает стандартный интерфейс OData.

**Что нужно сделать один раз в приложении Фреш:**
1. Открыть **Администрирование → Синхронизация данных → Настройки стандартного интерфейса OData**.
2. На вкладке «Авторизация» создать **служебного пользователя** — ему автоматически назначится роль «УдаленныйДоступOData» (отдельного пользователя для интеграции создавать безопасно и правильно).
3. На вкладке «Состав» включить доступ к **регистру бухгалтерии «Хозрасчетный»** и **плану счетов**.

**Адрес для запросов:** адрес приложения из браузера (без кода языка), например `https://1cfresh.com/a/sbm_demo/1962515`, плюс `/odata/standard.odata/...`. Аутентификация — логин/пароль служебного пользователя (HTTP Basic).

**Как это использует программа:** `api_client.py` умеет получать ОСВ напрямую из базы (метод `fetch_osv`, виртуальная таблица остатков и оборотов регистра) и превращать её в тот же «канонический» формат, что и файловую выгрузку, — дальше работают те же 5 проверок. Проверить соединение можно командой:
`python api_client.py <URL> <логин> <пароль> --start 2026-01-01T00:00:00 --end 2026-06-30T23:59:59`

**Ограничение Фреш:** данные можно только читать и записывать стандартным способом; режим обмена «обмен данными» через OData не поддерживается. Для чтения ОСВ это не мешает.
