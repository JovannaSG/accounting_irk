## [Не вышло]

### Исправлено
- Сортировка периодов приведена к календарной в проверках, сравнивающих
  соседние месяцы («зависшее сальдо», скачки оборотов): даты вида «дд.мм.гггг»
  раньше упорядочивались как строки, что ломало серию на границе годов
  (31.12.2025 vs 01.01.2026).
- Флаг «Зависшее сальдо между периодами» теперь доходит и до автопрохода
  по счетам (раньше работал только при обычном аудите); под чекбоксом
  появилась подсказка, что нужны данные за 2+ периода в одном запуске.
- Кнопки экспорта Excel/PDF теперь доступны и для баз, выбранных из истории
  (раньше появлялись только у проверок, запущенных в текущей сессии):
  находки и реквизиты отчета сохраняются в БД и восстанавливаются при выборе
  записи; для старых записей без сохраненных находок работает восстановление
  по таблице деталей.
- В мастер-таблице дашборда у проверок по контрагентам (4.5) теперь всегда
  заполнена колонка «Не закрыты документами, счет»: аванс и долг, расхождение
  документов и ОСВ больше не теряются; составные ячейки («60.01, 60.02»)
  разбиваются на отдельные счета.

### Добавлено
- Поддержка файла `.env` в корне проекта: настройки (ONEC_*, AUDIT_DB_PATH,
  AUDIT_USERS) автоматически загружаются при запуске через `app/run.py` и
  `streamlit run app/ui.py`; переменные, заданные в окружении напрямую,
  имеют приоритет. Раньше файл `.env.example` подразумевал ручной экспорт,
  который нигде не выполнялся.
- Ограничение доступа по ТЗ §11 (опционально): при заданной переменной
  окружения `AUDIT_USERS` («логин:хэш,…») перед работой открывается форма
  входа; пароли хранятся только в виде PBKDF2-HMAC-SHA256, хэш генерируется
  командой `python -m core.auth hash пароль`. Без переменной приложение
  работает без входа, как раньше.
- Журналирование пользователя: имя вошедшего фиксируется в истории аудитов
  (колонка `user`, БД мигрирует автоматически) и показывается в карточке
  базы на дашборде.
- Версия логики проверок (`AUDIT_LOGIC_VERSION`) записывается в метаданные
  каждого прогона; при экспорте записи из истории, созданной другой (или
  неизвестной) версией логики, показывается предупреждение, что находки
  могли вычисляться по другим правилам.
- Четвертый блок детальной панели дашборда «Расчеты с контрагентами» со всеми
  находками раздела 4.5 (раньше они были видны только внутри счетов).
- PDF: в объединенных разделах колонка «Проверка» печатается короткими метками
  («Аванс и долг», «Расчеты не закрыты», …), полностью пустые колонки скрываются,
  колонка «Счет» расширена, шрифт таблиц увеличен до 8pt.

### Добавлено
- Отчеты по принципу «сначала кратко»: в PDF перед детальными разделами
  выводятся блоки «Сводка по проверкам» и «Крупнейшие нарушения» (топ-10
  по сумме); в Excel появился первый лист «Обзор» с реквизитами, статусом,
  сводкой по проверкам и тем же топом.
- Excel: у листов с данными закреплена шапка, включен автофильтр, ширины
  колонок подобраны по содержимому, денежные колонки переведены в числовой
  формат с разделителями тысяч.

### Изменено
- Проверка «Зависшее сальдо (не меняется между периодами)» переведена в
  опциональные: по умолчанию выключена, включается параметром
  `stuck_balance_checks=True` или галкой «Зависшее сальдо между периодами»
  в боковой панели; одна находка теперь приходится на всю серию одинаковых
  остатков (в комментарии — дата начала «зависания» и число периодов),
  а не на каждый месяц отдельно.
- В PDF таблица «Итоги по разделам» заменена более подробной «Сводкой
  по проверкам» (по каждой проверке, а не по разделу).

## [1.0.0] — 2026-08-23

Первый релиз прототипа «ИИ-Аудитор 1С».

### Добавлено

**Проверки по ТЗ (§4)**
- 4.1 Красное сальдо — отрицательные остатки на активных счетах и дебетовые
  на пассивных; период возникновения находки.
- 4.2 Развернутое сальдо — одновременные Д и К остатки по одной аналитике.
- 4.3 Незакрытое сальдо на конец месяца + зависшее сальдо между периодами +
  опциональный контроль групп счетов (авансы, РБП, товары, денежные средства,
  кредиты).
- 4.4 Остатки на служебном счете 000.
- 4.5 Незакрытые расчеты с контрагентами — по реестру документов (с FIFO-возрастом
  долга и ожидаемым закрывающим документом) или эвристикой по ОСВ;
  расхождение документов и остатков ОСВ.
- Каждая проверка включается/отключается в боковой панели
  (`checks={"red_balance", ...}`).

**ML-проверки (statistical, unsupervised)**
- Нетипичные суммы операций по истории контрагента (медиана + MAD,
  настраиваемые пороги).
- Резкие скачки оборотов между периодами (рост и падение).
- Возможные дубли контрагентов — нечеткий поиск (rapidfuzz).

**NLP-проверка назначений платежей (115-ФЗ)**
- Rule-based сканирование колонки «Назначение» реестра документов:
  обнал, нетиповые переводы/комиссии, пожертвования между юрлицами,
  займы без ссылки на договор, расплывчатые основания без документа,
  наличная форма расчетов.
- Категория риска в комментарии находки («[Обнал] …»); тихий пропуск
  при отсутствии колонки; поддержка пользовательских ключевых слов.

**Отчеты (ТЗ §6)**
- Сводный отчет: статус, число флагов, суммы по видам проверок,
  рекомендации к каждой находке (ТЗ п.13).
- Детальный отчет с фильтрацией по проверке, счету и контрагенту.
- Экспорт в Excel (цветовая индикация красный/желтый, лист «Об отчете»)
  и PDF (fpdf2 + DejaVu, печатная форма с реквизитами).

**Данные и интеграции**
- Загрузка ОСВ из файлов: CSV / XLS / XLSX / HTML (реальные выгрузки 1С,
  многострочный заголовок, субконто с наследованием счета, БУ/НУ-ведомости);
  MXL не поддерживается.
- Опциональный реестр документов (CSV) для проверки 4.5 и NLP.
- Подключение к 1С:Фреш по OData (`core/api_client.py`): ОСВ напрямую из базы,
  помесячная загрузка, drill-down до аналитики счета.
- Тестовые данные для демонстрации без файлов.

**Интерфейс и инфраструктура**
- Streamlit UI: мастер-дашборд по базам, детализация по счетам (drill-down),
  история аудитов в SQLite со сравнением прогонов (исправлено/новое/осталось),
  аудит по выбранным счетам/контрагенту.
- Docker-развертывание (Dockerfile + docker-compose.yml, healthcheck).
- CI на GitHub Actions: ruff + pytest при push/PR.
- 173 автотеста (ядро, загрузчики, OData-клиент, ML/NLP, отчеты, UI).

### Известные ограничения
- Формат MXL не поддерживается (сохраните выгрузку как Excel/HTML).
- Обычная ОСВ не содержит аналитику — проверки 4.2/4.5 полноценно работают
  с выгрузкой с субконто или реестром документов.
- Аутентификация не встроена — ограничивайте доступ на уровне reverse proxy.
